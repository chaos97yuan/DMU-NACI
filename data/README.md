# Data

## 1. Source data (required, not redistributed)

All experiments use the **DKASC Alice Springs** (Alice Springs, Australia)
5-minute PV power and weather data, downloaded from the Desert Knowledge
Australia Solar Centre:

> **https://dkasolarcentre.com.au** — Data → Download (CSV export)

The raw export files are **not redistributed with this repository** because the
Solar Centre data licence does not grant blanket redistribution permission.
Users must download the data directly from the official source (free
registration-free export). Cite the DKASC Solar Centre as the data provider in
any derived work (see also the paper's Data Availability statement).

### Required exports and exact file names

Download **yearly CSV exports** and place them under `data/raw/` **renamed
exactly** as follows (the loaders hard-code these names):

| File | System | Used by |
|---|---|---|
| `Alice_Springs_2021.csv` … `Alice_Springs_2025.csv` | Site 18 (5.2 kW fixed-tilt) + shared weather station | Site 18 pipeline (`s1`–`s7`), vintage arm (`s5`), replay (`s4`) |
| same `Alice_Springs_{2022..2025}.csv` | Site 1B (23.4 kW dual-axis) columns inside the same export | Site 1B pipeline (`p2`–`p9`) |

The DKASC "Site 18" system export (source key `13`) contains the Site 18 power
channel and the co-located weather station; the **same download** also carries
the Site 1B (M9) power channel used by `common_1b.RAW_COLS`
(`87_DKA_M9_A_C_Phases_Active_Power`). One export set therefore serves both
systems, matching the paper's statement that both systems use meteorological
inputs from the same DKASC station.

### Raw schema (Site 18)

`src/data/schema.py:REQUIRED_RAW_COLUMNS` lists the exact CSV columns that are
read; the three-year file layout must match the DKASC export headers:

- `timestamp`
- `71_DKA_M2_C_Phase_Active_Power`
- `101_DKA_WeatherStation_Global_Horizontal_Radiation`
- `101_DKA_WeatherStation_Diffuse_Horizontal_Radiation`
- `101_DKA_WeatherStation_Radiation_Global_Tilted`
- `101_DKA_WeatherStation_Radiation_Diffuse_Tilted`
- `101_DKA_WeatherStation_Weather_Temperature_Celsius`
- `101_DKA_WeatherStation_Weather_Relative_Humidity`
- `101_DKA_WeatherStation_Wind_Speed`
- `101_DKA_WeatherStation_Wind_Direction`
- `101_DKA_WeatherStation_Weather_Daily_Rainfall`

`data/synthetic_example.csv` is a **synthetic** 3-day file in exactly this
schema (generated by `scripts/make_synthetic_example.py`); it contains no real
observations and is only for smoke tests and format checks.

## 2. Data policy

| Artifact | In repo? | Why |
|---|---|---|
| Raw DKASC CSVs (`data/raw/`) | **No** | No redistribution licence; download from the source above |
| Per-sample windows / cleaned cores (`X_*.npy`, `*_core.csv`) | **No** | Direct derivatives of the observations |
| Per-sample residuals / intervals (`*.parquet`, interval CSVs) | **No** | Functionally keyed to the observations |
| Aggregate metrics, manifests, selection decisions (`results/`) | **Yes** | Only derived statistics; these are the paper-evidence files |
| Trained model weights (`checkpoints/`) | **Yes** | Model parameters, not data |

## 3. Preprocessing and experiment splits (summary)

Full details: paper Section 3.1 and `configs/site18.yaml` (mirrors
`experiments/rigorous_v2/common_v2.py`, which is authoritative).

1. **Cleaning** (`scripts/02_clean_data.py`, frozen functions): unit QC on
   power/radiation/humidity/rainfall, variable-specific interpolation for
   *input* features only, segment bookkeeping. Missing values are **not**
   interpolated; windows whose inputs or target are incomplete/imputed are
   excluded.
2. **Causal-safe windows** (`src/eval/historical_interpolation_causality_audit.py`):
   input = 72 steps (6 h at 5 min) ending at the forecast origin; target =
   origin + 15 min; windows depending on future-interpolation endpoints are
   dropped.
3. **Chronological splits (Site 18, half-open intervals, Table 1)**:
   DEV `[2024-01-01, 2024-08-08)` with internal early-stop tail
   `[2024-07-17, 2024-08-08)`, SELECT `[2024-08-08, 2024-09-16)`,
   CALIB `[2024-09-16, 2024-10-02)`, SAME `[2024-10-02, 2025-01-01)`,
   CROSS = 2025. The 2025 targets never enter training, selection, or initial
   calibration; during sequential evaluation they reach the ACI recursion only
   after the prescribed 3-step feedback delay.
4. **2024/2025 "preopen" universes** (windows + difficulty-state labels
   `N_group`/`HARD_DF`): frozen artifacts built from the same raw data by the
   legacy builders preserved under `legacy/preopen_builders/` (see that folder's
   README and `MISSING_FILES.md` for their external dependency list).
5. **Difficult-state labels** (`src/features/dynamic_index.py`,
   `src/features/historical_familiarity.py`): evaluation-only, never used in
   training or calibration (paper Section 3.2).
